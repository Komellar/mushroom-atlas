# Phase 8 development validation and release preparation

Validation dates: 2026-10-09–10. Dataset: `0.7.0`.

Result: development checks passed; a standalone internal test APK was built, verified, and freshly launched offline. Native functional acceptance passed; remaining accessibility, rotation, storage, physical-device performance, and independent content review are recorded below. This report does not establish a completed release.

- Dataset validation and all 27 tests passed, including search normalization, scientific synonyms, combined filters, invalid/duplicate selections, reversible swapping, reference integrity, and both orders of every curated pair across 870 possible ordered different selections.
- TypeScript, ESLint, formatting, and the Android bundle export passed. Export verification found all 66 photographs and 66 thumbnails among the declared assets, with the bundle and local fonts present.
- The browser rendered all 30 detail pages and all 12 curated pairs in both orders. The expanded atlas → Łuszczak details → Galerina details → comparison → swap → atlas flow restored the query. Two- and three-photo boundary controls and enlargement/close passed. The dangerous lookalike comparison had no horizontal page overflow at 320 × 568, and application error logs were empty.
- Expo Doctor 1.20.4 passed 21/21 checks, and the SDK 57 dependencies passed Expo compatibility checking. Audit findings remain at 18 high and 11 moderate flagged packages; a compatible fix dry run proposed no changes. [The assessment](../dependency-assessment.md) records underlying advisories, installed paths, exposure inferences, and upgrade follow-up.
- A standalone internal APK profile is configured in `eas.json` and passed the official EAS schema validation. It does not include a development client. Cloud authentication and project ownership are unresolved; no cloud project or managed signing key has been created.
- Local Expo prebuild generated the ignored Android project. Required SDK 36, NDK, and CMake packages were installed using the host SDK's accepted licenses. Native compilation exposed Java 25 and incomplete Java 17 runtime issues; a full checksum-verified Temurin JDK 17 is prepared for the local build. No emulator was installed or launched.
- Android resource linking exposed a missing splash drawable. The splash plugin now explicitly references the bundled image, and regeneration produced the drawable at all five Android density levels. A shorter Gradle cache path and regenerated CMake caches resolved Ninja's Windows filename limit. The corrected release build passed in 9 minutes 34 seconds.
- The APK from revision `8e20e93` passed SHA-256 archive checks for all 66 photographs and 66 thumbnails, plus JavaScript and fonts. `apksigner` verified its v2 signature, and `aapt` confirmed the Polish label, package, version, launcher activity, SDK levels, and all four ABIs. The [build record](../android-release.md) includes artifact and certificate hashes. The generated debug certificate is appropriate only for internal testing.
- With explicit user authorization, ADB installed the APK on the already-running Pixel 10 Pro emulator (Android 17/API 37, 1280 × 2856, density 480, font scale 1.0). Fresh first launch passed with airplane mode on, Wi-Fi off, and Metro stopped: Polish guidance, 30 entries, navigation, and a local image rendered. The initial sequence was invalidated by test actions hitting the keyboard; the earlier attribution to other input was incorrect. After correcting the helper, native search, scientific/Polish synonyms, combined filters, empty feedback, and reset passed offline. See [the native record](../native-acceptance.md).
- [Build instructions](../android-release.md), [native acceptance](../native-acceptance.md), APK archive verification, image maintenance, attribution, and pending specialist review are documented. APK content verification will establish archive inclusion only; runtime offline behavior needs a fresh standalone installation.

The corrected native sequence also passed every detail page and all 66 gallery photographs, complete navigation with atlas state restoration, searchable selection, duplicate rejection, swapping, replacement, and Polish recovery screens. Phase 1 native acceptance is now complete on the existing emulator.

Follow-up on 2026-10-10: all 12 curated pairs passed both native orders, plus a generic pair. Large-font testing exposed obscured comparison rows and clipped tab labels; revision `cb093b1` fixed both. Its verified rebuilt APK passed fresh offline launch, all seven navigation cases, three focused comparison cases, 320 × 568 dp layouts at font scales 1.0 and 2.0, and three representative long-name comparisons at 2.0. Offline restart passed. Exhaustive detail/gallery and pair tests used the original APK; the rebuild received affected reruns and unchanged-asset hash verification.

Three fresh process starts recorded activity times of 870, 768, and 747 ms (median 768 ms; app data and OS caches retained). Emulator scrolling recorded 90/290 janky frames (31.03%) and 17/18/19/20 ms frame-time percentiles; performance remains a follow-up, not a pass. One interrupted run recorded an ANR correlated with Windows host sleep and a seven-hour clock jump; resumed cases passed. Original emulator settings were restored. See [native acceptance](../native-acceptance.md) for methods and limits.

Remaining acceptance: interactive TalkBack, rotation, installed-storage measurement, physical-device/performance follow-up, and independent review of descriptions, categories, photographs, and curated distinctions.
